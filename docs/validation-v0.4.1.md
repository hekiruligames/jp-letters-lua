# 0.4.1: 配信前の準備を保存して、あとで再開する

2026-10-11。保存済みかどうかを本文欄の下で確認し、ファイルへの保存・復元を折りたたみメニューから探す配置だった。配信前に準備して後日使うときに見つけやすいよう、画面上部へ **「準備の保存・読み込み」** を追加した。

![画面上部に並ぶOBSへの保存状況と、ファイルに保存・ファイルから読み込みのボタン](images/preparation-save-load-v0.4.1.png)

## 使い方

1. 本文・管理用のメモ・表示設定を準備する。入力中の下書きもOBSへ自動保存する。「一覧に保存」を押すと、一覧にも登録できる。
2. 上部の **「OBSに保存済み」** を確認して、操作画面を閉じる。配信へ表示する必要はない。
3. 後日、OBSの同じソースのプロパティにある **「お便りの操作画面を開く」** から再開する。OBSを再起動した場合も、このボタンから開き直す。

配信ごとに保管したい場合や、別のPCへ移す場合は、上部の **「ファイルに保存」** を使う。お便りの一覧・入力中の下書き・表示設定・操作画面の配色を1つのJSONにまとめ、PCの現地日時付きの名前でダウンロードする。保存先はブラウザの設定に従う。

**「ファイルから読み込み」** でそのJSONを選ぶと、置き換える内容を確認する。キャンセルすれば現在の内容を保つ。読み込んだ後の配信は非表示なので、プレビューを確認してから「このお便りを配信に表示」を押す。バックアップの形式は変更していない。

保存の失敗は **「OBSに未保存・再試行中」**、別の操作画面との競合は **「入力をこの画面に保持しています」** と上部へ表示する。どちらも「ファイルに保存」で画面に残った最新の入力を保管できる。ファイルの書き出しはOBSへの変更や配信への表示を行わない。

受信箱の取り込みボタンは一覧の下にある。本文の区切り貼り付け・テキストやJSONの追加は **「ほかの方法で取り込む」** へまとめた。

## 検証

実Linux libobs 30.2.3＋OBS LuaJITと実Chromiumで、Web30項目、OBS Lua6項目、フォント制限5通りを確認した。[機械可読の結果](validation-v0.4.1.json)。

[検証済みの配布ZIP](../releases/v0.4.1/jp-letters-0.4.1.zip)は76,287バイト。SHA-256: `f91d41e2678dc346990f057b32d1d4744c236d5dc53b93420b061715f405fa14`。

- ブラウザの新しいコンテキストで操作画面を開き、本文・メモ・一覧をOBSから再開する。保存状況とファイルの2ボタンが配信操作より上にあり、メニューを開かずに使える。
- 保存したJSONに一覧・下書き・表示設定・配色・表示中のスナップショットが含まれ、ファイル名に日時が付く。書き出しで配信を変えない。
- 読み込みボタンからファイル選択を開く。確認のキャンセルは全状態を保ち、実行後は準備を復元して配信を非表示にする。
- OBSへの書き込みを失敗させ、未保存の表示とファイルへの退避を確認する。OBSには上書きせず、ファイルには最新のメモが残る。接続を戻すと自動保存を再開する。
- 競合で保存を止めた操作画面でも、未保存の入力をファイルへ保管できる。
- 幅390〜1440pxで横のはみ出しとボタンの重なりを確認する。従来の取り込み・ページ・スクロール・フォント・配色・OBS保存と復元も検証する。
- スクリプト削除、再追加、繰り返しの再読み込みで、ソース・子描画・ホットキーの後始末を確認する。

ネイティブ側の子ブラウザはテスト用の描画ソースで代用し、HTMLは別の実Chromiumで確認した。macOS・WindowsのOBS実機と、Safari上の操作画面はこの環境で動かしていない。実機確認は [#9](https://github.com/hekiruligames/jp-letters-lua/issues/9) で継続する。

## 更新

更新前に準備のバックアップを保管し、OBSを終了する。既存フォルダの `jp-letters.lua` と `runtime`・`web` を新しいZIPの内容でまとめて上書きする。OBSを起動後、ソースのプロパティから操作画面を開き直す。[詳しい手順](../letters/README.md#旧版から更新する)。

0.4.0以前の画面では、ファイルへの保存は「取り込み・バックアップ → バックアップを書き出す」にある。
