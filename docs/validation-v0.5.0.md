# v0.5.0の変更と検証

2026-10-12。v0.5.0では「マシュマロ向け」表示プリセットと、利用者が選んだ画像を下中央に表示する機能を追加した。実装は[PR #27](https://github.com/hekiruligames/jp-letters-lua/pull/27)、マージ時のコミットは `393091bd9c22b751f2a3cccd9e82463949e471ec`。

## 利用者向けの変更

- 「マシュマロ向け」は外枠を `#F3969A`、カードを白、文字を黒にし、輪郭を外す。外側の余白は上・右・左16px、下64px。フォント、文字サイズ、行間、配置、角丸、カード内の余白、ページ番号、表示方式は保つ。
- カード内の「マシュマロ」は、設定欄のチェックで表示・非表示を切り替えられる。
- 利用者が用意したPNG・JPEG・WebP・GIFを1枚選び、下中央へ表示できる。1枚128KB以内。画像はOBSの保存データとバックアップJSONに含まれる。
- 新規ソースの初期値は文字32px、外側の余白16px、左揃え・上揃え。枠は960 × 540pxを保つ。既存のソースに保存された設定は引き継ぐ。

画像と表示設定の編集は準備中のプレビューへ反映する。「このお便りを配信に表示」を押すまで配信中の表示は変わらない。画像を外しても、配信に表示済みの画像は表示ボタンを押すまで保つ。

画像は外側の下の余白に入る。ほかの見た目でも画像を使う場合は、下の余白を64px程度に増やす。公式ロゴの同梱・自動取得は行わず、利用者が公式の利用条件を確認して画像を用意する。[詳しい使い方](../letters/README.md#下中央のアイコン)

## 公開準備中に修正した保存の不具合

保存前に始まった取得処理の結果が保存後に届くと、古い状態で画面を更新し、次の保存を「別の操作画面から更新されました」と判定するケースを再現した。修正前は、操作画面を1つだけ開いた検証でも同じ案内が出た。

取得処理を始めた時点の状態の更新番号と編集回数を記録し、応答が届くまでに保存や編集が進んだ場合は、古い取得結果を反映しないよう修正した。同じ条件で次の編集が保存できることを確認し、回帰テストへ追加した。別の画面で実際に変更した場合の競合防止と、未保存の入力をファイルに保管する機能も維持する。

## 開発環境での検証

Linuxのlibobs 30.2.3と実OBS LuaJIT、実Chromiumで検証した。Web側33項目、OBS Lua側6項目、フォント制限5通り、表示プリセットの単体テスト、Release添付処理8項目が通過した。

今回の追加確認は次のとおり。

- 保存前の取得結果を意図的に遅らせ、保存後に届かせる検証を追加した。新しい入力を上書きせず、次の編集も保存でき、配信中の表示を保つことを確認した。
- 新しい初期値と、旧版の48px・余白40px・中央配置の保存データの引き継ぎを確認した。
- プリセットが関係のない設定を保ち、表示設定の初期化ではお便り・下書き・配信中の表示・画面の配色を保つことを確認した。
- ブラウザの画像選択でプレビューに反映し、表示ボタンを押すまで配信中の表示を保つことを確認した。サービス名の表示切り替えも確認した。
- SVGと128KBを超えるファイルを拒否し、選択済みの画像を保つことを確認した。
- 実際に読み込める画像で縦横比・下中央の位置・下余白内への収まり、ピンクの外枠・白いカードを確認した。
- 画像を含むJSONを書き出し、読み込みで設定と画像が戻ることを確認した。読み込み直後は非表示になり、表示ボタンで再表示できる。
- 画像を含むOBSソースの保存・復元を確認した。従来の受信箱取り込み、追加フォント、ページ送り、スクロール、一括削除、自動保存、競合・接続切れ、390〜1440pxのレイアウトも確認した。
- ソースを残したスクリプト削除、再追加、3回連続の再読み込みを確認した。子ソースとホットキーの後始末、設定の維持も確認した。

ネイティブ側の子ブラウザはテスト用の描画ソースで代用し、HTMLは別の実Chromiumで確認した。Linuxの実OBS内蔵ブラウザを通した検証ではない。画像例の青い「JP」は検証用に作ったサンプルで、公式ロゴではない。

## Macの実機確認報告と残る確認

[PR #27の「macOS + OBS 実機確認」](https://github.com/hekiruligames/jp-letters-lua/pull/27)には、次の結果が記録されている。この開発環境でMacを操作した結果とは区別する。

- マシュマロ向け表示、設定変更、画像の表示が意図どおり動いた。
- OBSを終了すると、開いていた操作画面が切断表示になった。
- OBSを再起動しても以前の操作画面は自動で再接続しなかった。起動ごとに接続情報が変わる仕様どおりの動作。
- OBSから操作画面を開き直すと、最後に編集したお便り・表示設定・画像が復元された。
- JSONの保存・読み込みで、表示設定と画像まで復元された。

利用者の回答により、確認環境はMacBook Pro M5・メモリ24GB、macOS 26.6.2（25G83）、OBS 32.2.2、Safari 26.6.2（21624.5.1.11.3）と記録する。報告対象はPR #27の機能確認であり、今回の最終ZIPをMacで検証した記録ではない。公開準備中の保存の修正も、Macではまだ確認していない。Windowsの実機確認、Mac・Safariでの追加フォント・受信箱取り込み・スクリプト削除などは[#9](https://github.com/hekiruligames/jp-letters-lua/issues/9)で継続する。

## 配布と照合

`jp-letters-0.5.0.zip` に製品のLua・HTML・JavaScript・CSS、説明書、サンプル、GPL-2.0-or-laterのライセンス、`validation.json` を同梱する。開発用テストとよみやすは同梱しない。

検証後の製品コードとZIP内の全ファイルをSHA-256で照合する。検証結果は[validation-v0.5.0.json](validation-v0.5.0.json)にも記録する。JSONの `macOSRuntimeTested`・`windowsRuntimeTested` は開発環境のテスト対象を表し、両方とも `false`。上のMac実機報告は別記録として扱う。

ZIPのSHA-256: `a654fbce268e228d66a119606ea510252c68789f6d9b158c7fb7bdd0b8f479f4`

ReleaseにはZIPだけを添付する。GitHub Actionsで添付後、公開されたファイルをダウンロードして同じSHA-256であることを確認する。[公開処理の手順](release-attachment.md)

## 旧版からの更新

準備を「ファイルに保存」で保管し、OBSを終了してから、既存フォルダの `jp-letters.lua` と `runtime`・`web` を新しいZIPの内容でまとめて上書きする。OBSを起動後、ソースのプロパティから操作画面を開き直す。以前の画面には自動で再接続しない。[更新手順](../letters/README.md#旧版から更新する)

0.4.0以前では「取り込み・バックアップ → バックアップを書き出す」を使う。0.2.0・0.3.0ではスクリプト削除時の不具合があるため、OBSを終了してファイルを更新する。
