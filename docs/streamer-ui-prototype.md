# 配信者向けコンパクト操作画面（試作）

## 背景と想定する利用環境

14インチMacBook Proの1画面で、ブラウザのお便り操作画面とOBSの映像・チャットを左右に並べる。配信者はブラウザの本文を見ながら読み上げるため、本文の可読性を最優先とする。従来は配信操作が画面上部、表示ボタンが本文の下部にあり、1件紹介するたびにページを上下スクロールする必要があった。

この試作はv0.5.1の配布物を変更せず、専用ブランチでUIを検証する。既存のお便りデータ、設定保存形式、OBS Lua側のAPIは変更しない。

## 変更した画面構成

- 画面幅**1100px以下**では本文エディターを最初に表示する。お便り一覧・その他の表示設定・表示前プレビューは上部の3つのボタンから展開する。
- 配信操作は常時表示の画面下部ドックへ集約。「配信に表示」「配信から非表示」「紹介済み→次を準備」「紹介済み→次を表示」、配信中のページ送り・スクロールを一か所から行う。
- 枠の幅・高さと「文章に合わせる高さ」は本文近くの「枠のサイズ」に置く。数値変更はまず準備中にのみ反映され、配信中の表示を変更するには明示的に「配信に表示」を押す。
- 画面上部の「ファイルに保存」「ファイルから読み込み」と自動保存状態は常時利用できる。読み込みが**現在の一覧全体を置き換える**既存仕様も維持する。
- 大きな画面では従来の3カラム表示を維持し、既存機能や設定を削らない。詳細設定パネルからフォント、余白、配色、アイコン画像の調整が引き続き可能。
- ボタンやパネルはARIA状態とキーボード操作を維持し、狭い画面で自動保存を含む既存の操作を行える。

## 配信時の操作

1. お便りを選ぶ（リストを開く）。ブラウザの本文を読む。
2. 画面下部の「このお便りを配信に表示」を押す。
3. 配信中に読む位置の操作、非表示、必要ならカードの高さを調整する。高さ調整後の反映は「このお便りを配信に表示」を押す。
4. 読み終えたら「紹介済み→次を表示」を1回押すか、配信への切り替えを避けたいときは「紹介済み→次を準備」を押す。
5. 最後のお便りが終わったとき、次を表示するボタンは無効になり、紹介済みだけを記録して終われる。

## 注意と検証項目

- 「紹介済み→次を表示」は、次に表示できる本文について描画レイアウトの検証が済んだ場合だけ現在の状態を変更する。次がなければ古いお便りを勝手に再表示しない。
- 表示前プレビューを閉じても、既存の描画・ページ計算は生きており、必要に応じて開ける。
- OBSに表示中の状態と本文／デザインの準備状態は分離したままにする。
- 720pxや390pxで固定ドックが画面外にはみ出さないこと、入力欄と配信操作に到達できること、一覧と設定が開閉できることをChromium E2Eに追加した。
- Linuxのlibobs/OBS LuaJIT/Chromiumと実機macOS Safari＋OBSの結果は区別する。配信中の操作感と表示密度は最終的にMacで確認する。

この試作は、Unload/Archiveには触れない。正式配布は別途レビュー・実機確認後に判断する。
