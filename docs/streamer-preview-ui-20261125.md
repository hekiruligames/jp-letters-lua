# 配信者向けUI 第2試作（2026-11-25）

## 実機フィードバックと設計判断

- 前試作 PR #32 では本文入力欄を中心にしたため、配信者が大きなマシュマロ風カードを見て読むという実際の使い方と合わなかった。左一覧がなく残件数と次の内容も分からなかった。設定の移動は不便だった。
- v0.5.1を起点に、左一覧・中央プレビュー・本文編集・従来の設定パネルを維持。画面幅540px以上では一覧とプレビューが横並び。540〜1100pxでは詳細設定をプレビューの下の右列に限定する。540px未満では縦に並ぶ。
- 大きな上部配信パネルを縮小し、全幅で下部の固定操作バーに表示・非表示・紹介済み→次を表示・紹介済み→次を準備・ページ送り・スクロールを集約。現在表示中と次候補の識別名を表示。
- 緑の塗りつぶしは有効な「次を表示」、薄い表示は無効。次候補は従来の準備操作と同じルール（別の準備済み下書きがあれば優先、それ以外は次の未紹介）。次がない場合は以前の内容を再表示しない。
- 幅・高さ・自動高さはプレビュー上で簡易調整でき、従来の詳細設定と同期。変更の反映は明示的な表示操作のみ。
- 保存・読み込み・既存のデータ形式・OBS Lua APIは維持。本文編集、配信表示と準備表示は引き続き分離。
- 旧試作PR #32は未マージのまま比較記録として残す。今回の試用版の識別子は 0.5.2-preview.3（正式リリースではない）。

## 検証・試用

GitHub Actionsで既存のLinux libobs/OBS LuaJITとChromiumテスト、および720×760でプレビューと一覧が同時に見えること、下部固定操作、緑の有効色、次への遷移、簡易高さの同期、保存・復元を確認する。成功時にパッケージとテスト画像をActions artifactへ保存する設定を追加した。実行結果はActionsで確認し、Mac/Safari/OBS実機での使いやすさは別途確認する。LinuxのOBSブラウザAPIはテスト用の代替である。

試す前に既存版のJSONを保存、OBSを終了し旧フォルダを丸ごと退避。新旧のスクリプトを二重登録せず元のパスに試用版を置き、OBSから操作画面を開き直す。元に戻す場合はOBSを終了して退避フォルダを戻す。
